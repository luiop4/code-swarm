# 0.4.1 混合与流式动画

0.4.1 修复高速输入反复重置缓动的问题：按实际帧间隔追赶最新目的地，输入更新只延长显示时间。默认每 80ms 捕获一次，并在后续帧立即调度积压任务。

新增默认启用的自动跟随，滚动到最近写入的行；末行也会参与动画。滚动只改变视口，保留选区、编辑器内容和焦点。用户向上查看、鼠标选择或键盘导航时暂停跟随，点击状态栏“跟随暂停”或运行“继续跟随最新代码”恢复；`codeSwarm.followStreaming=false` 关闭。跟随支持混合模式，滚动和首次定位仍有短暂延迟。

| 编辑内容 | 视觉效果 |
|---|---|
| 连续新增、行尾追加 | 彩色输入光标、短尾迹、下划线；新片段延长现有光标的行程 |
| 小段替换 | 拖选、旧文本淡出、新位置短暂强调 |
| 删除 | 红色旧文本残影被擦除、碎粒散开；无悬浮框，不划掉当前行的新内容 |
| 大段粘贴/替换 | 多个悬浮代码片段，虚拟鼠标并行搬运 |
| 识别到的代码块移动 | 源位置向目标位置拖动的卡片 |

默认 `hybrid`，另有 `cards`、`cues` 保留旧效果。原生指针默认 12 DIP，卡片速度默认 4。没有任务时窗口隐藏。

## 为什么流式不会饿死

原来的捕获每次变化都会重置计时器；持续写入时永远等不到暂停。原来的定位还要求测量前后文档版本相同，流式输入会令测量结果不断作废。

现在从第一笔变化开始按 80ms 固定周期提交快照差异。定位依赖视口而不是内容版本，缓存几何约一秒，并独立复测。等待测量时最多保留一份合并快照；渲染端追加任务，不清空已有动画。同一行的输入任务按行号合并，最多 96 个在途任务；不为每个字符创建一个鼠标。

聊天焦点不再要求 `activeTextEditor` 必须是源文件，改从 `visibleTextEditors` 找已监听 URI。语言切换或 AI 替换文档模型时按 URI 重新绑定。只捕获 VS Code 已向该文档同步的内容，不声称识别编辑来自哪个 AI。

## 位置和边界

使用零宽临时绿色标记测量代码列和行距。标记约显示 140ms，截图只在内存中识别，不保存、不上传。初次变化及随后约一秒复测一次；中间批次复用坐标，侧栏展开引起的横向变化在下一次测量时修正。布局刷新会有短暂延迟，不能做到任意工作台布局逐像素同步。

混合定位针对单一、未折叠、关闭自动换行的可见区域。当前可见范围分裂或开启自动换行时暂停定位并提示；比例字体、复杂内嵌视图、水平滚动和装饰造成的字符宽度差异仍可能影响横向精度。可使用旧 `cards` 模式或独立舞台；没有修改 VS Code 安装文件或注入内部 DOM。

原生 Copilot 高亮属于 VS Code 窗口，不能通常遮住置顶原生覆盖。但 Copilot 的临时预览、独立差异模型或尚未提交到源文档的内容可能没有目标文档事件；这种情况仍无法通过通用公开 API 保证捕获。`Code Swarm: 查看覆盖状态` 可查看动画批次、定位次数和等待原因；它不会记录源文本。

## 文件安全

捕获、差异分析和原生绘制只读。没有通过动画逐字符写文件，没有自动保存或为播放回退代码。真实修改继续由 AI/VS Code 完成；结构化补丁保留原来的版本校验、预览和单次可撤销提交。磁盘与未保存缓冲区冲突时不覆盖任何一方。

## 运行验证

```powershell
npm ci
npm run check
npm test
$env:VSCODE_EXECUTABLE_PATH = 'C:\Program Files\Microsoft VS Code\Code.exe'
npm run test:overlay
npm run test:extension
npm run package
```

原生测试应保持新开的测试窗口在前台；测试使用独立配置和合成 Python 文件，不修改用户项目。可设置 `SWARM_FOCUS_WAIT=30000` 留出切到测试窗口的时间。测试中连续写入 80 次，期间采样状态，要求生产者结束前已有多批可见动画、同一行光标续接，并检查聊天焦点、侧栏展开后坐标刷新、输入/替换/删除/卡片混合、模型替换保持监听、有界队列、磁盘不被动画保存、空闲隐藏。
