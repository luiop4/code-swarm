# 0.3 悬浮代码卡片

目标是“代码被拆成许多悬浮小框，虚拟鼠标把小框搬到对应行”。旧的轻量提示保留为 `cues` 模式，Windows 默认使用 `cards`。

## 动作

- 小框先在代码区的临时卡片区悬浮出现，展示代码片段、行号和 BUILD / REPLACE / MOVE / DELETE 标记。
- 小指针靠近卡片角落，抓住卡片，沿不同曲线路径飞向目标行。
- 途中保留淡色路径、落点辅助线与少量倾斜；落位时缩小、吸附、散开少量光点，然后消失，露出原生代码。
- 删除使用旧文本红色卡片，划线后收走、缩小，不在其他实时文本上划删除线。
- 替换采用青色卡片、搬运采用紫色卡片；小鼠标保留自己的颜色。空闲鼠标始终隐藏。

## 任务密度与语义

`src/core/cardPlan.ts` 是只读的视觉规划器。普通小改动按原始增、改、删、移语义拆片；每个非空行按最多约 24 个代码点进一步拆分，保留目标行和视觉列偏移，避免把多行修改只表现成一个光标。

演示或变更量达到 20 个增删行时，会根据最终快照重建**当前可见视口**，其中可能包含这次没有变化的行；状态提示明确标注重建。这是视觉施工编排，不代表每张卡片都是一个真实 AI 操作。整文件删除仍展示旧文本移除卡片，不因最终文件为空而丢掉动画。

最多 80 张卡片，默认最多 32 个指针并行，后续卡片分批接力。屏幕外的代码不会被强制滚动到面前；滚动后可以重新运行卡片重建命令。片段位置以行定位为基础，列偏移和卡片尺寸为估算，不能当作字符级编辑器选择范围。

## 速度

原始预览每张卡片约 5 秒，按用户反馈将默认 `codeSwarm.cardSpeed` 调为 `2.5`：单张卡约 2 秒，短暂错峰进场；多波卡片的总时长随任务数增加。可调范围 `0.5–4`。加速不改变真实文件写入时机。

## 新变化与手动操作

AI 再次修改文档时，旧场景先进入短暂悬浮/淡出，下一场开始时保留部分离场卡片，避免整层突然清空。尚未稳定的多次修改会合并到最新快照，不无限堆积场景。定位测量暂时隐藏原生窗口并等待桌面合成器完成，避免把上一场卡片当成定位标记。

手动键盘/鼠标选择、滚动、失焦或布局变化仍会取消覆盖。原生层只检测 Ctrl/Alt 是否按下以避让快捷键，不记录任何键入内容。点击穿透、版本保护、原生撤销与源文件写入的隔离继续保留。

## 验证

- 9 个核心用例通过，包含大段代码产生多张卡片、可见范围限制、Unicode 保留、整文件删除仍产生移除卡片。
- 实际 VS Code Extension Host 验证一场 24 张可见卡片和 24 个小指针，原生文件未被演示修改。
- 验证新场景衔接时保留离场卡片；滚动取消、真实编辑触发、删除卡片及空闲隐藏通过。
- 加速回归要求这组单波场景时长小于 3.1 秒。
- 通过 Windows 原生动画窗口实际预览检查卡片框、文本、指针、曲线路径和落位效果。

这不是对 Codex/Copilot/Claude 内部编辑事务的拦截。AI 的真实代码可能先一次性出现，然后播放卡片重建；源文件不会因视觉过程而逐段改写或反复保存。
