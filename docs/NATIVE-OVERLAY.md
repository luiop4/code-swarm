# 0.2 原生覆盖：实现与限制

## 0.2.2 兼容修复

在实际用户窗口中复现了“等待对齐”：请求 12 个定位点，却识别到 14 个连通区域。原因是零宽标记与真实代码重叠，前景字形把同一定位条切成了多个区域。修复会合并边界重叠的同一字形碎片；相邻行的满块字符可能接触，因此还将相邻行分批测量。批次之间若窗口尺寸或代码列位置变化，就放弃旧结果，避免混用布局。

该修复增加了几何回归用例，并在字体大小 19、行高 23 的真实 Extension Host 中验证生成、单处修改、删除、滚动取消和空闲隐藏。随后在用户原来的 VS Code 窗口中实际验证：完整演示成功识别 11/11 定位点并创建 11 个任务；外部修改 `ytg.py` 顶部前缀后，编辑器自动载入新文本，成功识别 2/2 定位点并启动 1 个原生覆盖任务，文档为已保存状态。

此外修复了失败没有足够诊断信息的问题。“查看覆盖状态”会把位置/数量/窗口/文档版本状态记录到该扩展的 VS Code 日志目录，不含源代码。未保存缓冲区与外部磁盘版本不一致时，状态栏和一次通知会提示先解决版本差异，不自动覆盖任何一方。

新增“预览当前打开的补丁 JSON”命令，支持直接打开模型输出的 JSON 后走已有差异预览及版本检查流程。应用仍是独立的原生编辑事务，可撤销。

用户体验改为直接在真实代码编辑区播放动画。Windows 默认使用原生模式，Webview 保留为可选的完整重建演示。

- 默认指针 10 DIP（可设置 6–16），无悬浮姓名；Webview 指针也缩小一半。
- 仅绘制时间线上正在执行的任务。没有空闲环绕、边缘排队或停车区；完成后隐藏整个窗口。
- 不替换原生编辑器，不抢键盘，不模拟系统鼠标点击。真实编辑、补全和调试仍在原生编辑器内进行。

## 边界

`native/Overlay.cs` 是独立 C# / WPF 程序，基于 .NET Framework 4.8。通过标准输入接收有界的定位与绘制消息，通过标准输出返回定位结果与状态。没有网络监听端口、任意命令执行、源文件读写或保存接口。

窗口使用 `AllowsTransparency`、`WS_EX_LAYERED`、`WS_EX_TRANSPARENT`、`WS_EX_NOACTIVATE` 和工具窗口样式，避免遮挡输入、抢焦点、出现在任务栏。仅在绑定的 VS Code 窗口处于前台时绘制。调试用 `--inspect` 例外，可临时显示窗口条目，以便检查透明表面；正式运行不使用此参数。

依赖的官方能力：

- [VS Code 不允许扩展直接访问工作台 DOM](https://code.visualstudio.com/api/extension-capabilities/overview#restrictions)
- [TextEditorDecorationType、文档变化与可见范围](https://code.visualstudio.com/api/references/vscode-api)
- [Windows 分层窗口及点击穿透](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#layered-windows)
- [不激活窗口与扩展样式](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles)
- [WPF 透明窗口](https://learn.microsoft.com/en-us/dotnet/api/system.windows.window.allowstransparency)

## 对齐测量

扩展 API 没有公开任意原生字符的屏幕坐标，因此没有假设顶部工具栏固定为多少像素，也没有通过调试端口读取内部 DOM。

1. 仅筛选当前活动文档、当前视口中的任务。
2. 为目标行第 1 列添加临时零宽装饰，使用饱和绿色矩形字符。显示约 180ms 等待合成器更新；源文本、真实选择与布局不变。
3. 辅助程序确认绑定窗口是前台 VS Code，并且标题包含当前文件名，然后仅捕获该窗口客户端区域到内存。
4. 用颜色饱和度与矩形连通区域检测定位条；要求只有一个明确的列，且检测数量与请求数量完全一致，按逻辑行排序关联。该方式已在用户本机存在透明背景效果的 VS Code 中测试。
5. 立即移除装饰。找不到整组可信位置时不猜测坐标，不显示覆盖动画。相邻行定位点用于测量行距，宽度为字体与实际像素比例的估算。

定位标记会短促闪现，这是当前原型的明确取舍。自定义主题、对比度、遮挡、折叠、横向滚动、特殊布局或其他同色装饰可能使识别失败。第 1 列不在屏幕中时会失败，而不是把动画画错。复杂软换行、双向文本、非常规字体、所有分屏组合未实测。第一版不承诺字形级精确边界；起始行定位来自检测，选区宽度与代码卡片尺寸为估算。

内存截图仅用于一次定位计算，不写入图片、不上传、不记录图像历史。协议中只传递位置、任务类型及最多 500 字符的局部展示文本；源文件真实写入仍只在扩展的独立补丁流程中发生。

## 取消与生命周期

滚动、活动编辑器变化、源文本再次变化、编辑器配置变化、VS Code 失焦都会清除任务并使正在等待的测量结果失效。窗口平移只更新覆盖窗口坐标；窗口大小或 DPI 变化取消动画，下一次变化/重播重新测量。屏幕外任务不绘制，不挤到边缘。

任务完成后窗口隐藏；空闲检测降到 500ms，不持续画空画布。停止监听、切换演示、扩展退出都会关闭子进程并移除装饰；超时后终止自己的子进程。工作区未受信任时不启动原生程序。远程工作区以 UI 扩展运行在本地，但 SSH/WSL 等组合未实测。

## 视觉语义

文件监听是结果发生后的可视化。原生覆盖不把真实文本擦除并伪造重新输入：生成与修改显示紧贴代码的输入指示和选区，移动显示局部悬浮代码卡，删除显示短暂旧片段提示。鼠标数量是视觉工作者数量，不是模型调用数量。原生选区不是用户的实际选择。

纯演示模式使用当前文档的只读快照进行任务生成，不修改当前文件。补丁预览和真实提交的版本保护、撤销边界仍沿用上一版。

## 本机测试

`npm run test:overlay` 在真实 VS Code Extension Host 内执行：

- 建立原生监听，不打开 Webview。
- 自动找到 15 个实际代码定位点，调度 14 个可见任务，指针尺寸为 10 DIP。
- 纯演示前后源缓冲区和磁盘文件完全一致。
- 滚动立即取消旧位置的任务；修改真实缓冲区触发新覆盖任务。
- 删除回放使用旧文本悬浮片段，不在已经占据原位置的其他代码上划删除线。
- 任务结束后可见指针数为 0，窗口完全隐藏；断开释放原生实例。

辅助程序 `--self-test` 在独立测试窗口验证 Windows 命中测试返回下层窗口、前台焦点保持在源窗口、平移跟随、改变大小时取消，以及结束后窗口隐藏。本机结果 `clickThrough=true`、`focusSafe=true`、`tracksMove=true`、`canceled=true`、`visible=false`。使用 `--self-test --inspect` 检查了实际小指针与悬浮代码卡的绘制外观。

构建需要 Windows 自带 .NET Framework 编译器，脚本使用 `Framework64/v4.0.30319/csc.exe`；运行不需要 .NET SDK 或 PowerShell 执行策略变更。尚未做跨机器、所有屏幕比例、所有多显示器组合与代码签名分发验证。
