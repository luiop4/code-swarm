# 常见问题

[返回首页](../README.md)

### 为什么 AI 改完代码才看到动画？

普通监听收到的是变化后的通知。Copilot Agent 工具也需要先收到 Agent 提交的完整代码，再开始动画应用。需要在模型响应期间就输入，请使用“让 VS Code AI 流式写入当前文件”命令和可用模型。

### 能直接接管所有 Codex / Claude / Copilot 吗？

不能通用拦截所有工具的写入。Copilot Agent 可主动调用 `#swarm_animate_edit`；其他扩展可调用适配器 API；外部生成器可改写本次会话的暂存副本。直接修改真实文件仍属于事后观察。

### Copilot 没有使用 Code Swarm？

确认 Agent 模式下启用了 Code Swarm 工具，输入 `#swarm_animate_edit` 并从补全中选择。要求它将完整结果交给工具，在普通文件编辑之前调用。先聚焦目标本地文件，再回到聊天窗口。

### 写入旧的 `.swarm-...` 文件没有反应？

暂存路径是会话专属的。重新启动通用动画输入后，使用新复制的路径；旧路径不会自动重新连接。真实目标文件需要保持可见，编辑时发生竞争修改会终止会话。

### 状态一直是“等待定位”？

保持编辑器前台、目标代码可见。关闭自动换行，展开可见区域折叠，减少水平滚动，再运行继续或重播。复杂布局、缩放和遮挡会影响当前定位方案。原生定位采用短暂装饰与内存测量，不注入 VS Code DOM。

### 动画会把代码保存到磁盘吗？

动画输入编辑的是 VS Code 缓冲区，扩展不主动保存。VS Code 自动保存设置仍然生效。不要将“扩展不保存”理解为关闭了编辑器自动保存。

### 出现人工编辑或外部文件变化怎么办？

动画输入会检查文档版本、内容和磁盘状态。冲突时停止待处理输入，保留当前内容和备份，不自动回滚覆盖人工编辑。请使用 VS Code 的冲突处理与备份视图。

### 动图代表原生覆盖的实际效果吗？

首页 GIF 直接录自 Windows VS Code 和原生覆盖层。首页 GIF 展示只读卡片重建，高清 MP4 还展示真实编辑器输入与修改反馈。示例代码由脚本供给，没有调用真实模型。原视频按原速录制，GIF 进行了片段剪辑、缩放和抽帧。见 [录制说明](DEMO.md)。实际效果受布局、DPI 和定位结果影响。
